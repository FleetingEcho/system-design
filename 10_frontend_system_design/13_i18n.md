# 国际化（i18n）方案

> i18n（Internationalization）不只是翻译文字，还包括：日期/数字/货币格式、
> 复数规则、RTL 布局（阿拉伯语/希伯来语）、时区处理、翻译工作流。

---

## i18n 核心问题

```
1. 文本翻译（最基础）
   "Submit" → "提交" / "Soumettre" / "إرسال"

2. 复数规则（各语言不同）
   英语：1 item / 2 items（两种形式）
   俄语：1 товар / 2 товара / 5 товаров（三种形式）
   阿拉伯语：六种形式

3. 日期/时间格式
   中国：2024年1月15日  美国：January 15, 2024  德国：15. Januar 2024

4. 数字/货币格式
   1,234.56（英语）/ 1.234,56（德语）
   $1,234.56 / ¥1,234 / €1.234,56

5. RTL 布局（Right-to-Left）
   阿拉伯语、希伯来语、波斯语从右向左读写
   整个页面布局镜像翻转

6. 时区处理
   服务端存 UTC，显示时转换用户本地时区
```

## next-intl（Next.js 首选）

### 项目结构

```
messages/
  en.json       ← 英语（基准语言）
  zh.json       ← 中文
  ar.json       ← 阿拉伯语
  de.json       ← 德语

src/
  i18n.ts       ← next-intl 配置
  middleware.ts ← 语言检测 + 路由
```

### 配置

```typescript
// src/i18n.ts
import { getRequestConfig } from 'next-intl/server';

export const locales = ['en', 'zh', 'ar', 'de'] as const;
export type Locale = typeof locales[number];
export const defaultLocale: Locale = 'en';

export default getRequestConfig(async ({ locale }) => {
  // 按需加载翻译（不加载所有语言）
  const messages = (await import(`../messages/${locale}.json`)).default;

  return {
    messages,
    // ICU 消息格式配置
    formats: {
      dateTime: {
        short: { day: 'numeric', month: 'short', year: 'numeric' },
        long: { weekday: 'long', day: 'numeric', month: 'long', year: 'numeric' },
      },
      number: {
        currency: { style: 'currency', minimumFractionDigits: 0 },
        precise: { minimumFractionDigits: 2, maximumFractionDigits: 4 },
      },
    },
  };
});
```

```typescript
// src/middleware.ts — 语言检测和路由
import createMiddleware from 'next-intl/middleware';
import { locales, defaultLocale } from './i18n';

export default createMiddleware({
  locales,
  defaultLocale,
  localeDetection: true,     // 从 Accept-Language header 检测
  localePrefix: 'as-needed', // /en/... 但默认语言用 /...（无前缀）
});

export const config = {
  matcher: ['/((?!api|_next|.*\\..*).*)'],
};
```

### 在组件中使用

```typescript
// app/[locale]/products/[id]/page.tsx
import { useTranslations, useFormatter } from 'next-intl';

export default function ProductPage() {
  const t = useTranslations('product');
  const format = useFormatter();

  const product = { name: 'iPhone 16', price: 5999, stock: 3, rating: 4.8 };

  return (
    <div>
      <h1>{t('title')}</h1>

      {/* 变量插值 */}
      <p>{t('price', { price: format.number(product.price, 'currency') })}</p>

      {/* 复数规则（ICU 格式）*/}
      <p>{t('inStock', { count: product.stock })}</p>
      {/* 英语：3 items left | 中文：剩余 3 件 */}

      {/* 日期格式化 */}
      <p>上架时间：{format.dateTime(new Date('2024-09-25'), 'short')}</p>
      {/* 英语：Sep 25, 2024 | 中文：2024年9月25日 */}
    </div>
  );
}

// Server Component 中使用（getTranslations）
import { getTranslations } from 'next-intl/server';

export async function generateMetadata({ params: { locale } }) {
  const t = await getTranslations({ locale, namespace: 'product' });
  return { title: t('title') };
}
```

## react-i18next（非 Next.js 项目）

```typescript
// i18n/config.ts
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import LanguageDetector from 'i18next-browser-languagedetector';
import Backend from 'i18next-http-backend';

i18n
  .use(Backend)           // 从服务器懒加载翻译文件
  .use(LanguageDetector)  // 自动检测浏览器语言
  .use(initReactI18next)
  .init({
    fallbackLng: 'en',
    ns: ['common', 'product', 'checkout'],  // 命名空间（按页面/功能拆分）
    defaultNS: 'common',
    backend: {
      loadPath: '/locales/{{lng}}/{{ns}}.json',
    },
    interpolation: {
      escapeValue: false,  // React 已处理 XSS
    },
    detection: {
      order: ['querystring', 'cookie', 'navigator'],
      caches: ['cookie'],
    },
  });

// 组件中使用
import { useTranslation, Trans } from 'react-i18next';

function WelcomeBanner({ user }: { user: User }) {
  const { t, i18n } = useTranslation('common');

  return (
    <div>
      <p>{t('greeting', { name: user.name })}</p>

      {/* Trans 组件处理含 HTML 的翻译 */}
      <Trans i18nKey="privacyNotice">
        By continuing, you agree to our{' '}
        <a href="/terms">Terms of Service</a> and{' '}
        <a href="/privacy">Privacy Policy</a>.
      </Trans>

      {/* 切换语言 */}
      <select value={i18n.language} onChange={e => i18n.changeLanguage(e.target.value)}>
        <option value="en">English</option>
        <option value="zh">中文</option>
        <option value="ar">العربية</option>
      </select>
    </div>
  );
}
```

## RTL（右到左）布局支持

### CSS 逻辑属性

```css
/* ❌ 方向固定，RTL 时布局错乱 */
.sidebar { margin-left: 16px; padding-right: 24px; border-left: 1px solid; }
.icon { float: left; }

/* ✓ 逻辑属性，自动适配 RTL */
.sidebar {
  margin-inline-start: 16px;  /* LTR: margin-left; RTL: margin-right */
  padding-inline-end: 24px;   /* LTR: padding-right; RTL: padding-left */
  border-inline-start: 1px solid;
}
.icon { float: inline-start; }

/* 逻辑属性对照表 */
/* margin-left/right     → margin-inline-start/end  */
/* padding-top/bottom    → padding-block-start/end  */
/* border-left           → border-inline-start      */
/* left/right (position) → inset-inline-start/end   */
/* text-align: left      → text-align: start        */
```

```typescript
// 根据语言方向设置 dir 属性
const RTL_LANGUAGES = new Set(['ar', 'he', 'fa', 'ur']);

function RootLayout({ locale, children }: { locale: string; children: React.ReactNode }) {
  const dir = RTL_LANGUAGES.has(locale) ? 'rtl' : 'ltr';

  return (
    <html lang={locale} dir={dir}>
      <body>{children}</body>
    </html>
  );
}
```

### Tailwind CSS RTL 支持

```html
<!-- Tailwind v3 使用 rtl: 修饰符 -->
<div class="ml-4 rtl:mr-4 rtl:ml-0">
  <!-- LTR: margin-left: 1rem; RTL: margin-right: 1rem -->
</div>

<!-- 推荐使用逻辑属性插件 -->
<!-- ms-4 = margin-inline-start: 1rem（自动适配方向）-->
<div class="ms-4 pe-6">
  <!-- ms = margin-start, pe = padding-end -->
</div>
```

## 日期/时间/货币格式化

### 使用 Intl API（浏览器原生）

```typescript
// 日期格式化
const formatDate = (date: Date, locale: string): string => {
  return new Intl.DateTimeFormat(locale, {
    year: 'numeric', month: 'long', day: 'numeric',
  }).format(date);
};

formatDate(new Date('2024-01-15'), 'en-US');  // "January 15, 2024"
formatDate(new Date('2024-01-15'), 'zh-CN');  // "2024年1月15日"
formatDate(new Date('2024-01-15'), 'ar-SA');  // "١٥ يناير ٢٠٢٤"
formatDate(new Date('2024-01-15'), 'de-DE');  // "15. Januar 2024"

// 货币格式化
const formatCurrency = (amount: number, locale: string, currency: string): string => {
  return new Intl.NumberFormat(locale, {
    style: 'currency',
    currency,
    minimumFractionDigits: 0,
  }).format(amount);
};

formatCurrency(1234.56, 'en-US', 'USD');  // "$1,235"
formatCurrency(1234.56, 'zh-CN', 'CNY');  // "¥1,235"
formatCurrency(1234.56, 'de-DE', 'EUR');  // "1.235 €"

// 相对时间（"3 分钟前"）
const rtf = new Intl.RelativeTimeFormat('zh-CN', { style: 'long' });
rtf.format(-3, 'minute');   // "3分钟前"
rtf.format(2, 'day');        // "2天后"
```

### 时区处理

```typescript
// 服务端：所有时间存 UTC
// 客户端：显示时转换用户时区

// 获取用户时区
const userTimezone = Intl.DateTimeFormat().resolvedOptions().timeZone;
// "Asia/Shanghai" / "America/New_York" / "Europe/Berlin"

// 正确的时区显示
const formatLocalTime = (utcDate: Date, timezone: string, locale: string): string => {
  return new Intl.DateTimeFormat(locale, {
    timeZone: timezone,
    year: 'numeric', month: 'short', day: 'numeric',
    hour: '2-digit', minute: '2-digit',
    timeZoneName: 'short',
  }).format(utcDate);
};

// "Jan 15, 2024, 08:00 AM CST"（上海时区查看纽约时间）
formatLocalTime(new Date('2024-01-15T00:00:00Z'), 'America/New_York', 'en-US');
```

## 翻译工作流

### 流程设计

```
开发者写代码
  → 使用 t('product.newFeature', 'Default text') 或 key
  → CI 提取新 key（i18next-scanner / formatjs extract）
  → 推送到翻译平台（Lokalise / Crowdin / Phrase）
  → 翻译人员翻译
  → CI 同步翻译回仓库
  → 发布
```

### CI 提取 + 同步

```bash
# package.json scripts
"i18n:extract": "formatjs extract 'src/**/*.{ts,tsx}' --out-file messages/en.json --id-interpolation-pattern '[sha512:contenthash:base64:6]'",
"i18n:compile": "formatjs compile messages/en.json --ast --out-file compiled/en.json",
"i18n:sync": "lokalise2 file upload --token $LOKALISE_TOKEN --project-id $PROJECT_ID --file messages/en.json --lang-iso en"
```

```yaml
# GitHub Actions — 提取并同步到 Lokalise
- name: Extract i18n keys
  run: pnpm i18n:extract

- name: Check for new keys
  run: git diff --exit-code messages/en.json || echo "New i18n keys found"

- name: Push to Lokalise
  if: github.ref == 'refs/heads/main'
  run: pnpm i18n:sync
```

### 翻译 Key 命名规范

```
命名空间.页面/功能.描述

✓ good:
  common.button.submit
  product.detail.price
  checkout.form.email.label
  error.network.timeout

✗ bad:
  btn1           （无意义）
  submitButton   （没有命名空间）
  text123        （数字后缀，不可维护）
```

## 面试常见追问

**Q: 翻译文件放服务端还是客户端？**
A: 两者都需要。服务端（SSR）渲染时需要翻译（避免 FOUC）；客户端需要翻译处理用户交互。next-intl 通过 Server Components 在服务端加载翻译，客户端 bundle 不包含翻译文件（减少 bundle 大小）。

**Q: 如何处理翻译缺失（missing key）？**
A: 三层降级：①当前语言翻译 → ②fallback 语言（通常英语）→ ③key 本身（显示原始 key，便于发现问题）。生产环境用监控捕获 missing key 事件，发送告警。

**Q: RTL 支持成本高吗？**
A: 如果从一开始用 CSS 逻辑属性，成本可控。如果是已有项目改造，成本很高（需要审查所有 left/right 用法）。Tailwind 的 `rtl:` 修饰符和逻辑属性插件可以简化改造。建议新项目从第一天起用逻辑属性。

**Q: i18n 对性能有影响吗？**
A: 主要影响是翻译文件的加载大小。优化：①按路由懒加载翻译（只加载当前页面需要的）；②使用 CDN 分发翻译文件（长缓存）；③翻译文件 Gzip 压缩（文本重复率高，压缩比好）；④next-intl 在服务端处理，翻译不进客户端 bundle。
