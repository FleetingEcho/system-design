# 概念速查表：50 个核心术语

面试前 5 分钟扫一遍。每个词能用一句话准确解释即可。

---

## 基础指标

| 术语 | 一句话解释 |
|------|-----------|
| **Latency（延迟）** | 一个请求从发出到收到响应的总时间 |
| **Throughput（吞吐量）** | 系统单位时间内能处理的请求数（QPS/RPS）|
| **Availability（可用性）** | 系统正常工作时间占总时间的比例（几个九）|
| **P99 Latency** | 99% 的请求在这个时间内完成；最慢的 1% 超过这个值 |
| **SLA** | 对外签的服务承诺，违反有代价（合同级别）|
| **SLO** | 内部制定的目标，比 SLA 更严格，留有缓冲 |
| **SLI** | 实际测量到的指标值（是 SLO 达成的证据）|
| **Error Rate（错误率）** | 失败请求占总请求的比例 |

## 一致性与可用性

| 术语 | 一句话解释 |
|------|-----------|
| **CAP 定理** | 分布式系统只能同时满足 CP 或 AP，P 不可放弃 |
| **ACID** | 数据库事务的四个特性：原子性、一致性、隔离性、持久性 |
| **BASE** | 分布式系统的一致性模型：基本可用、软状态、最终一致 |
| **强一致性（Linearizability）** | 写完后，所有读操作立即看到新值 |
| **最终一致性（Eventual Consistency）** | 停止写入后，所有副本最终会有相同的值 |
| **因果一致性（Causal Consistency）** | 有因果关系的操作保序，无因果关系的并发操作可乱序 |
| **读己写一致性（Read-Your-Writes）** | 用户总能看到自己刚才写入的数据 |
| **Quorum（法定人数）** | W + R > N 保证读一定能读到最新写入 |

## 分布式系统

| 术语 | 一句话解释 |
|------|-----------|
| **网络分区（Network Partition）** | 集群中部分节点无法互相通信 |
| **脑裂（Split Brain）** | 两个节点都认为自己是主节点，各自接受写入 |
| **共识（Consensus）** | 多个节点对某个值达成一致，即使有节点故障 |
| **Raft** | 易理解的共识算法，用于 Leader 选举和日志复制 |
| **Paxos** | 共识算法的理论奠基，难理解，实际工程用 Raft 居多 |
| **Leader 选举** | 集群在主节点故障后选出新主节点的过程 |
| **Backpressure（背压）** | 下游处理太慢时，上游主动限速，防止被压垮 |
| **幂等性（Idempotency）** | 操作执行多次与执行一次结果相同 |
| **At-least-once** | 消息至少被投递一次，可能重复，不会丢失 |
| **Exactly-once** | 消息被且只被处理一次，最难实现 |

## 存储

| 术语 | 一句话解释 |
|------|-----------|
| **分片（Sharding）** | 把数据水平切割分散到多台机器 |
| **一致性哈希（Consistent Hashing）** | 添加/删除节点时只有少量数据需要迁移的哈希算法 |
| **B+ Tree** | 数据库索引的常用数据结构，叶节点链表支持高效范围查询 |
| **LSM Tree** | Cassandra/RocksDB 的存储结构，写入追加，读时合并，写快读慢 |
| **WAL（Write-Ahead Log）** | 预写日志，保证崩溃后数据可恢复（持久性的实现基础）|
| **Binlog** | MySQL 的二进制日志，用于主从复制和数据恢复 |
| **覆盖索引（Covering Index）** | 查询所需列都在索引里，不需要回表 |
| **回表（Index Lookup）** | 二级索引查到主键后，再查主键索引获取完整行数据 |
| **复制延迟（Replication Lag）** | 从库数据落后主库的时间 |
| **MVCC** | 多版本并发控制，读不加锁通过版本快照实现隔离 |

## 缓存

| 术语 | 一句话解释 |
|------|-----------|
| **Cache-Aside** | 读时懒加载，写时删缓存；最常用的缓存模式 |
| **Write-Through** | 写时同步更新 DB 和缓存，强一致但写慢 |
| **Write-Back** | 写时只写缓存，异步写 DB，写极快但可能丢数据 |
| **缓存穿透（Cache Penetration）** | 查不存在的 Key，每次都打到 DB；布隆过滤器解决 |
| **缓存击穿（Cache Breakdown）** | 热点 Key 过期瞬间大量并发请求打到 DB；互斥锁或逻辑过期解决 |
| **缓存雪崩（Cache Avalanche）** | 大量 Key 同时过期或 Redis 宕机，全部打到 DB；TTL 加抖动解决 |
| **布隆过滤器（Bloom Filter）** | 用极小空间告诉你"某元素一定不存在"或"可能存在" |
| **TTL（Time To Live）** | 缓存/DNS 记录的有效期，到期后失效 |
| **热 Key（Hot Key）** | 单个 Key 访问量极高，打满单个 Redis 节点 |

---

## 通信

| 术语 | 一句话解释 |
|------|-----------|
| **幂等 Key（Idempotency Key）** | 客户端生成的唯一 ID，服务端用于防止重复处理 |
| **Fanout（扇出）** | 一条消息分发给多个接收者（如推文推送给所有粉丝）|
| **Push vs Pull** | 推：服务端主动发；拉：客户端主动取；推拉结合：两者混用 |
| **长轮询（Long Polling）** | 服务器挂起请求直到有数据，比短轮询高效 |
| **SSE** | 服务器单向推流，基于 HTTP，适合通知和实时数据 |
| **gRPC** | 基于 HTTP/2 + Protobuf 的 RPC 框架，高性能类型安全 |
| **API Gateway** | 微服务的统一入口，处理鉴权、限流、路由 |

---

## 容错

| 术语 | 一句话解释 |
|------|-----------|
| **熔断器（Circuit Breaker）** | 下游故障率超阈值时快速失败，避免级联崩溃 |
| **令牌桶（Token Bucket）** | 限流算法，允许短时突发，长期速率受限 |
| **降级（Fallback）** | 核心功能不可用时，返回简化或默认响应 |
| **指数退避（Exponential Backoff）** | 重试等待时间指数增长 + 随机抖动，避免重试风暴 |
| **Saga** | 微服务分布式事务模式，每步有补偿操作，最终一致 |
| **TCC** | Try-Confirm-Cancel，业务层显式锁定资源，比 Saga 一致性更强 |
| **2PC（两阶段提交）** | 分布式事务协议，强一致但有阻塞和单点问题 |
| **Outbox 模式** | 把消息和业务数据写入同一 DB 事务，保证消息不丢失 |
| **Error Budget（错误预算）** | SLO 允许的失败额度，用来决策是否应该发布 |
